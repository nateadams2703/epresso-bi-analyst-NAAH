# $1,000 modified-data test (Guide Sections 6 and 8)

**Status:** complete, Oct 29, 2026. Parts 1–2 (the modified row and the predictions) were written and
pushed **before** the upload (commit `a67af25`) and have not changed since. Parts 3–4 record the
results, including a failed first attempt and the improvement that came from it.

The test shows that the app recalculates from whatever data is loaded: one revenue value goes
up by exactly $1,000, the file is uploaded through the app with no code changes and no restart,
and we compare what happened with what we predicted.

### Improvement from the first attempt: a fingerprint for each loaded file (fix and retest)

- **Finding:** two files can share a name (`data/Sales.csv` and `data/modified/Sales.csv`), and
  the app showed both as "Sales.csv (uploaded)". A tester couldn't tell from the screen which
  one was loaded, so the first attempt looked like an app failure.
- **Fix:** a new function, `data_prep.loaded_summary()`, gives each table's row count, plus the
  revenue sum for Sales. The sidebar's "Loaded from" list and the "Loaded tables" table now
  show it, e.g. `Sales: Sales.csv (uploaded) · 25,200 rows · revenue sum $42,175,440.00`, with a
  caption saying to check these numbers after every upload.
- **Tests:**
  - `test_fingerprint_tells_two_files_with_the_same_name_apart` (`tests/test_data_prep.py`):
    uploads the original and the modified `Sales.csv`. Both are named `Sales.csv` and both show
    as "uploaded", with the same row count; the revenue sums differ by exactly $1,000.00.
  - `test_fingerprint_shows_sources_and_missing_tables`
  - `test_sidebar_shows_rows_and_revenue_sum_for_each_loaded_file` (`tests/test_app.py`)
- **Retest (local, Streamlit 1.66, the real upload widget driven by an automated browser),
  Oct 29:**

  | Upload | Sidebar: Sales | Total revenue |

  | `data/Sales.csv` (the first-attempt mistake) | Sales.csv (uploaded) · 25,200 rows · revenue sum **$42,174,440.00**, so the mistake is visible at once | Exactly $42,174,440.00 |
